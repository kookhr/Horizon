## [$5.6B Stolen from Binance in Historic Crypto Hack](https://arkm.com/explorer/entity/21a94755-f604-45e5-9501-6542e23005e8) ⭐️ 9.0/10

On October 29, approximately $5.6 billion was stolen from Binance hot wallets, with Circle and Tether moving to freeze roughly $2.4 billion in USDC and USDT across Ethereum and Tron networks linked to the suspected attacker wallets. The stolen amount vastly exceeds Binance's SAFU emergency insurance fund, which was valued at only $1 billion as of January 2022. This is potentially the largest crypto exchange hack in history, and the $5.6B loss far exceeds Binance's $1B SAFU fund, meaning user losses may not be fully covered. The event raises profound questions about the security of centralized exchanges and the paradox that stablecoins' centralized freezing mechanisms—while helpful here—undermine crypto's decentralization ethos. Specific frozen amounts include 971.15M USDT and 823M USDC on Ethereum, 312.73M USDT on Tron, and 175M USDT on Ethereum, though community members report the attacker may still be actively swapping out of USDT despite the freezes. The SAFU fund, established in July 2018 and funded by 10% of trading fees, is held in BTC in a separate cold wallet and is insufficient to cover the $5.6B loss.

## [Van der Waerden number W(2;3,21)=416 proved with Lean 4 kernel-checked neuro-symbolic proof](https://www.reddit.com/r/MachineLearning/comments/1xivpue/w2321_416_a_van_der_waerden_number_conjectured_by/) ⭐️ 9.0/10

The van der Waerden number W(2;3,21)=416, conjectured by Kullmann in 2010 and still listed as open by DeepMind's Formal Conjectures this year, has been formally proved using a Lean 4 kernel-checked proof generated by LPM (Large Proof Model), a neuro-symbolic system from Hupyy. The proof spans 209 cases with 38,661,140 verified leaf formulas, each refutation checked by cake_pr (an LRAT checker verified in CakeML) and bound by cryptographic digest to its Lean term. This resolves a 15-year-old open conjecture in combinatorics using a neuro-symbolic system with full formal verification, demonstrating that AI-assisted theorem proving can now tackle problems previously beyond automated methods. The rigorous kernel-checked methodology and massive 13.6 GB evidence package set a new reproducibility standard for machine-generated mathematical proofs, potentially reshaping how the mathematical community validates AI-produced results. The proof establishes that every red-blue coloring of {1,...,416} contains a red 3-term or blue 21-term arithmetic progression, while some coloring of {1,...,415} avoids both. Nothing was counted unless the Lean kernel or cake_pr accepted it, and the full evidence package—including Lean sources, checker records, and a replay kit—can be independently verified by downloading it and running 'shasum -a 256 -c SHA256SUMS'.

**Background**: Van der Waerden's theorem, a foundational result in Ramsey theory, states that for any positive integers r and k, there exists a smallest number N such that any r-coloring of {1,...,N} must contain a monochromatic arithmetic progression of length k; this N is the van der Waerden number. The notation W(2;3,21) refers to an asymmetric two-color case: the smallest N guaranteeing either a 3-term progression in the first color or a 21-term progression in the second. CakeML is a formally verified implementation of ML whose correctness guarantees extend to proof checkers like cake_pr, which verifies LRAT (Linear Resolution Asymmetric Tautology) proofs commonly used in SAT solving. LPM (Large Proof Model), developed by Hupyy, Inc., is a neuro-symbolic system designed to bridge abstract human intent and mathematically verified execution by combining neural guidance with symbolic verification.

## [Chained PHP2Shell and Linux XFRM Exploit Compromises 25 Government Servers](https://dreamgroup.com/blog/chained-php2shell-exploit-roots-25-servers) ⭐️ 8.0/10

A forensic report by Dream Group revealed that attackers chained the PHP2Shell vulnerability (CVE-2026-109618/CVE-2026-109619) with a Linux kernel XFRM ESP-in-TCP vulnerability to achieve root-level compromise of 25 servers, including US Government infrastructure. The exploit chain first leveraged memory safety flaws in PHP 5.4–8.5 for remote code execution, then escalated privileges via the kernel XFRM subsystem. This incident demonstrates a real-world successful exploitation of chained vulnerabilities against high-value government targets, highlighting how combining a web-layer RCE with a kernel privilege escalation can bypass defense-in-depth strategies. It underscores the persistent risk posed by the Linux kernel's large attack surface and the urgency of patching both application and kernel layers simultaneously. The PHP2Shell vulnerabilities (CVE-2026-109618 and CVE-2026-109619) are memory safety flaws affecting PHP versions 5.4 through 8.5, enabling remote code execution. The second stage exploited a Linux kernel XFRM subsystem vulnerability related to ESP-in-TCP packet handling; community members noted the initial payload required approximately 383MB of memory, suggesting some clumsiness in the exploit's memory exhaustion technique.

hackernews · 882542F3884314B · Oct 29, 10:42 · [Discussion](https://news.ycombinator.com/item?id=50286987)

**Background**: PHP2Shell refers to a pair of high-impact vulnerabilities (CVE-2026-109618 and CVE-2026-109619) in PHP versions 5.4–8.5 that allow remote code execution through memory safety flaws, potentially giving attackers full control of the web host. The Linux XFRM subsystem manages IPsec transformations, including the ESP (Encapsulating Security Payload) protocol, and has been the subject of multiple recent vulnerabilities such as CVE-2026-43107 and CVE-2026-43284 (Dirty Frag). A chained exploit combines two or more vulnerabilities sequentially — typically an initial remote code execution followed by a local privilege escalation — to achieve full system compromise that neither vulnerability could accomplish alone.
