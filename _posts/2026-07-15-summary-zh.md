## [Thinking Machines 发布 Inkling：支持音频的开放权重多模态模型](https://thinkingmachines.ai/news/introducing-inkling/) ⭐️ 8.0/10

Thinking Machines 推出了 Inkling，这是一个支持音频、文本和视觉多模态输入的开放权重模型。Inkling 并非号称整体最强的模型，而是被明确定位为可在 Tinker 平台上进行微调的可定制基础模型。 此次发布意义重大，因为它提供了目前最大的原生支持音频的开放权重模型，填补了开源生态中音频能力落后于文本和视觉的空白。它还验证了一种可行的商业模式：企业可以拥有并微调自己的模型，成本可能远低于依赖前沿闭源模型，同时为 DeepSeek 等占据主导地位的中国开放权重模型提供了美国替代方案。 Inkling 并非目前可用的整体最强模型，但其多模态能力、高效推理以及在 Tinker 平台上的微调可用性使其成为强大的开放权重基础模型。社区成员已经开始创建本地部署方案，包括通过 Unsloth 提供的 GGUF 和 NVFP4 量化版本，以及支持 Inkling 的 llama.cpp 分支。

hackernews · vimarsh6739 · 7月15日 18:12 · [社区讨论](https://news.ycombinator.com/item?id=48924912)

**背景**: 开放权重模型允许用户获取已训练的模型参数，使组织能够在不依赖专有 API 的情况下针对特定用例微调模型。多模态模型将文本、图像和音频等多种数据类型整合到单一统一网络中，从而实现音频推理和视觉问答等任务。对基础模型进行微调涉及在特定领域数据上进行进一步训练，这可以生成在专业任务上以更低成本超越通用前沿模型的模型。开放权重生态系统此前主要由 DeepSeek 等中国实验室主导，一家美国实验室提供具有竞争力的开放基础模型代表着值得关注的转变。

## [研究员绕过 Claude web_fetch 安全防护，窃取用户私密记忆数据](https://simonwillison.net/2026/Jul/15/claude-web-fetch-exfiltration/#atom-everything) ⭐️ 8.0/10

该漏洞表明，即使是 Anthropic 等主要 AI 厂商精心设计的确定性安全防护机制也可能被绕过，将用户最敏感的对话数据暴露给攻击者。它凸显了在防范将不可信网页内容与访问私密信息相结合的提示注入攻击时，LLM 智能体安全面临的持续挑战。 该攻击利用了 web_fetch 跟踪已获取页面中嵌入 URL 的能力，创建了一系列嵌套链接，从而绕过了 Anthropic 仅允许获取用户输入或 web_search 返回 URL 的规则。蜜罐网站仅向 user-agent 中包含 Claude-User 的客户端提供恶意内容以避免被检测，Anthropic 随后已通过移除 web_fetch 导航至已获取内容中链接的能力来修复该漏洞。

rss · Simon Willison · 7月15日 14:21

**背景**: 由 Simon Willison 提出的 AI 智能体"致命三要素"描述了一种危险的组合：LLM 既能访问私密数据，又处理不可信内容，还能与外部通信——这使得提示注入攻击能够窃取敏感信息。Anthropic 的 web_fetch 工具专门设计用于防止此类攻击，仅允许导航到用户自行输入的精确 URL 或其配套 web_search 工具返回的 URL。然而，web_fetch 被允许跟踪已获取页面中嵌入的链接，这造成了一个意料之外的攻击面，破坏了该确定性防护机制。

Telegram 正式推出了 Serverless 平台，允许开发者将机器人和 Mini App 的后端代码直接运行在 Telegram 自有基础设施上。开发者只需编写 JavaScript 模块并运行 `npx tgcloud push` 命令即可完成部署，无需再自行配置服务器或管理容器。 此举大幅降低了机器人开发者的基础设施开销并简化了部署流程，标志着 Telegram 平台能力的重大扩展。它使 Telegram 成为机器人和 Mini App 开发的更完整生态，降低了开发者的入门门槛。 部署的代码运行在紧邻 Bot API 的隔离 V8 沙箱中，并自带一个基于 SQLite 的内置数据库。这种架构确保了与 Telegram 核心服务的低延迟通信，同时为开发者提供了开箱即用的基础数据存储功能。
